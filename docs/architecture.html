Layers

Every load gets a new batch_id and passes through six layers in this order, as the client's blueprint specifies.

Core tables and links

jira_requests holds one row per valid ticket; its AI review columns follow the REVIEW SCHEMA in the scored workbook's "Request Review Design" sheet. The five ref_ tables are TABLE A to E from the same sheet and govern the values in those columns.

Core columns

The core tables with their columns. PK is the primary key, FK a foreign key the database enforces, and required means the column is never empty.

jira_requests

5,344 rows

How the tables could be improved

  • Add a list of allowed sub-types to the sheet, so those can be checked too.
  • Save the workbook's "Duration (Days)" values. The column only holds formulas without results, so every duration is calculated instead.
